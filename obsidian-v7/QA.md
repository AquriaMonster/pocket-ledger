# Pocket Ledger 2.0 · Mobile revision

## Source and storage
The financial script is byte-identical to the original at GitHub commit `be6d634293af3513dd3e8b5ca940fc69fe3f07f6`. Its SHA-256 is `46688437a8a0dfbe9a23cb0db42a462c0ccb67891321f4456840427e9e9f7ee9`. The test fixture contains the script from that exact source. The visual reference is Lovable commit `d2052854e54c20f2778730b8d96b4e8f9063ebe8` from project `18b0d798-250a-4298-a4b3-ffaea7557e2c`.

The app retains the v1 JSON schema, original account IDs, original date/amount validation and audit/revision rules. The IndexedDB database is the same isolated **review** database used by the preceding review build. The new app-shell cache is versioned separately and scoped to the worker registration. The app has no network service, analytics or external font dependency. All exercises used fictional data.

## Interface decisions
The middle button is a real 56 px button in the navigation grid. SVG paths, icons and text share their parent button's click handler. The wallet uses the prototype's engravings, locally bundled Fraunces/Manrope fonts, account colors, share ring, orbital hero and scroll-snap interaction. Added a wallet position indicator and keyboard focus for the scrolling wallet. The new bottom sheet follows the actual Lovable AddSheet and ReviewView composition. Six type choices remain visible; the category rail and account pickers are populated from the ledger. The amount editor uses the saved unit, including fractional thousands. Notes, Jalali date and historical edits remain available. A scrollable editor sits between the title and a separate Review footer. Review shows projected account balances at the selected month end and relevant debt using the original engine. Confirm performs the revision-checked write; Edit returns to the same draft.

The static interface uses the MIT Motion One v10.16.4 spring generator locally for sheet travel, review/page transitions and orbital parallax. Its parameters follow those in Lovable's Motion components. The generator is bundled as readable JavaScript with type annotations removed and utility arithmetic inlined. A full React conversion would have replaced working storage and form integration without changing the animation solver used here. CSS and native browser controls handle scroll, focus and the modal. Privacy removes the spending plot, interactive slider, category bars, and balance-weighted ring segments. Decorative contours stay visible.

## Repeating the checks
The static app itself requires no package installation. The three Node commands above use only built-ins. For a local Playwright smoke run, install Python Playwright and its Chromium binary and run `python tests/browser.py`. Set CHROMIUM if using a specific executable. Set ENGINE=webkit after installing the Playwright WebKit binary to try the same smoke test in WebKit.

For the longer rendered suite use Python with `websockets`, a disposable browser profile, and a dedicated synthetic review origin. Run the preview server on port 18785, open http://127.0.0.1:18785/ in that profile with its local DevTools port set to 19285, then run `QA_PORT=18785 python tests/rendered.py` (set the variable in your shell first on Windows). Start on an empty review origin for each run. For optional axe checks, set AXE_JS to a local copy of axe-core 4.10.3. Keep the browser debugging endpoint local. Screenshots and accessibility results are written under this package.
